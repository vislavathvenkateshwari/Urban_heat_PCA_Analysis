# PCA Analysis of Urban Heat — Software Simulation

## What this project does
This college-project demo creates synthetic (illustrative) environmental observations for an Urban zone and a Green zone. It standardizes seven features, applies PCA, plots PC1 against PC2, shows component loadings, flags unusual observations with Isolation Forest, and lets you download results as CSV.

**Important:** The displayed values are simulated. They are not real sensor readings, satellite observations, or scientific findings about a specific city. No hardware is needed to run this version.

## Requirements
- Windows 10/11, macOS, or Linux
- Python 3.10 or newer recommended
- Internet connection only to install the packages (the app itself runs locally)

## Step-by-step setup (Windows)
1. Download and extract the ZIP file to a folder, for example `Desktop\pca_urban_heat_project`.
2. Install Python 3.10+ from https://www.python.org/downloads/. During installation on Windows, tick **Add Python to PATH**.
3. Open the extracted folder in File Explorer.
4. Click the address bar, type `cmd`, and press Enter to open Command Prompt in that folder.
5. Create a virtual environment:
   ```bat
   python -m venv .venv
   ```
6. Activate it:
   ```bat
   .venv\Scripts\activate
   ```
7. Install dependencies:
   ```bat
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   ```
8. Start the dashboard:
   ```bat
   streamlit run app.py
   ```
9. A browser tab should open at the local address shown in the terminal (usually `http://localhost:8501`).
10. Use the sidebar to change the number of observations or simulation seed. Click **Generate simulated dataset** to make another dataset.
11. Review zone summaries, temperature trend, PCA plot, explained variance, loadings and anomaly flags.
12. Click **Download simulated readings and PCA results as CSV** to save the output for your report.

## What to explain in your viva
- **Urban Heat Island:** Built-up materials can store and release heat differently from vegetated areas.
- **Simulation:** Values are generated by code to test the workflow; they are not field measurements.
- **Standardization:** Features have different units and scales, so they are standardized before PCA.
- **PCA:** Re-expresses correlated measurements as principal components that capture directions of variation.
- **Loadings:** Help interpret which features contribute to each component.
- **Anomaly detection:** Isolation Forest flags observations that look unusual compared with this generated dataset. A flag does not itself prove heat danger.
- **Limitations:** Synthetic distributions are assumptions, and PCA does not prove causation. A real study needs calibrated measurements, suitable sampling, quality control, and appropriate validation.

## Why an ESP32 sketch is included
The optional `optional_esp32/esp32_dht22_http.ino` is only for a future hardware extension. It is **not needed** for the no-hardware simulation, and the current Streamlit app does not read its HTTP endpoint. It illustrates how a real ESP32/DHT22 could serve readings over a local network if hardware is added later.

## Project files
- `app.py` — Streamlit simulation, PCA, anomaly flags, charts and CSV export.
- `requirements.txt` — Python packages.
- `optional_esp32/esp32_dht22_http.ino` — optional future hardware sketch.
